# OKF Workbench 0.4.0 release record

Status: Publication blocked by headed QR-002 performance and unavailable signing key;
no 0.4.0 tag or package has been published.

## Scope

Node 24/CommonJS Extension Host output, `@types/node` 24.13.3, VS Code 1.123 minimum,
and VSCodium 1.126.04524 qualification, as accepted in [ADR 0012](../decisions/0012-node24-extension-host.md).
Development dependency updates include undici, fast-uri, js-yaml, postcss, and nanoid.
The format semantics, local-first behavior, Wasm ABI, and native CLI features are unchanged.

Headed Windows qualification exposed a dropped-watcher-event bug: the selected root's
`Uri.path` retained `/C:/`, while VS Code delivered `/c:/` events. The watcher now compares
URIs after VS Code's canonical serialization, preserving the original event URI and
the existing containment checks. A regression covers create/change/delete with nested
Unicode/spaced paths and rejects siblings and other drives.

The release candidate also enables the existing headed-evidence runner to read Windows
process CPU/working-set counters and invoke the editor's supplied Windows CLI wrapper.
CPU/working-set values remain environment-specific observations.

The complete [Windows performance report](../evidence/performance/vscode-1.129.1-0.4.0-windows-blocked.md)

gate, not a passing performance claim. The Ryzen 9 9900X / RTX 5070 Windows observation
does not establish behavior on the historical Mac reference environment.

Local type checking, formatting, focused lint, and watcher regression checks pass.

environment failure: Windows denies creation of the symbolic-link fixture with `EPERM`.

skipped to conceal the local limitation.

No configured usable signing key was found on the Windows release workstation. The
maintainer was asked for the existing key path or signing environment, without requesting
private-key contents. The signed-tag requirement has not been bypassed.

Results for PR #47, the earlier `dee7631` 0.4.0 candidate, and published 0.3.0 remain
predecessor evidence and are not reused as proof for changed package bytes.
